# SCAT 自動追尾（uv環境）

機器を使わない星像画像1枚のpixelズレ検証は [test_all/README_pixel_test.md](test_all/README_pixel_test.md) と実行済みノートブックを参照してください。

仕様書の方法2（Streamlit操作）を実装しています。uvプロジェクトは `observation` 直下です。
親の `tsuboi_lab` のPython 3.12環境とは分け、Python 3.11を使用します。
依存関係の正本は `observation/pyproject.toml` です。

## 起動

`tsuboi_lab/observation` で以下を実行します。

```powershell
uv sync
uv run streamlit run scat_observation/scat_guide_tracking_system/app_auto_guide.py
```

uvがPATHにない場合は `& "$env:USERPROFILE\.local\bin\uv.exe"` を `uv` の代わりに使用します。
`uv sync` はPython 3.11・依存関係・`.venv`・`uv.lock`を準備します。
以後、プログラムとテストは必ず `uv run` で実行してください。

初期設定はシミュレーションです。機器には接続しません。
「準備開始」→接続・冷却完了→「追尾開始」→各画像でスリット・点源検出→「追尾終了」→「カメラ接続オフ」の順で操作します。
終了後もアプリは残り、再準備・再追尾ができます。アプリを終了する前に接続オフを押してください。
複数ブラウザは同じカメラと操作状態を共有します。アプリプロセスの多重起動はしないでください。

## 構成

- `app_auto_guide.py`: 操作画面、画像・スリット・対象・補正値表示。
- `src/auto_guide.py`: 状態管理、撮像・解析・送信ループ、補正係数更新。
- `src/base__atik_camera_contloer.py`: ASCOMカメラ制御。既存の `atik_camera.py` を利用。
- `src/base__point_detector.py`: スリットと最大5個の点源検出。
- `src/base__fits_utils.py`: FITS読み込み、最新 `.fit` の置換保存。
- `src/base__client_sender.py`: 提供されたMoTコードに基づくTCP/JSON送信。
- `.config`: TOML設定。変更後はアプリを再起動。

## 実機設定

1. AtikドライバーとASCOM Platformを導入する。
2. 既定の `guide_slit_mode = 'science'` は各撮像画像からスリットを検出するため、参照画像を読み込まない。
   `guide_slit_roi = [880,250,1130,850]` は現在の検証画像用。実際の撮像画像でスリット全体が入るよう調整する。
   `reference` に切り替える場合だけ `flat_path` と `slit_roi` を使用する。
3. 冷却温度・露光時間を調整する。
4. `matrix` の単位・符号・回転を実測で校正して `calibration_confirmed = true` にする。
5. `mot_host`、`mot_port`、`mot_timeout_sec` を確認し、`simulation = false` にして再起動する。

MoT送信形式は提供コードと同じです。

```json
{"command":"guide","ra offset":1.0,"dec offset":-1.0}
```

既定接続先は `10.91.80.225:8744`。接続ごとに1回送信し、応答を受信して切断します。
タイムアウト時の二重補正を避けるため自動再送しません。
元コードに応答の成功判定・フレーム終端・補正量の単位が定義されていないため、
既定では非空応答の受信のみを確認します。これは機械動作の成功確認ではありません。
成功応答が確定した場合は `mot_expected_response` にその文字列を設定できます。
RA/Decの単位はコントローラーと校正行列を一致させてください。

## 検出と制御

- scienceモードは毎フレームで、星像の明るさを制限した解析画像から細長い暗領域を抽出し、
  向きと位置のそろった断片を結びます。検出端点の中点をスリット中心として更新します。
  スリット検出に失敗すると、過去の位置を流用せず停止します。
- 点源を局所ピークから抽出し、背景差引き9×9画素の積分光量で順位付けします。
  `target_brightness_rank = 1` は最も明るい点源。その後は近傍の同一対象を追います。
- 画面のoffsetはスリット−対象の(x,y) pixel。補正は `gain × matrix × offset`。
  `deadband_px` 内では送信せず、`max_correction` で各軸の最大値を制限します。
- 前回の送信量と次画像の移動から行列を逐次更新し、初期行列の0.5～2倍の範囲に制限します。
  大きな移動や逆応答では更新せず、追尾開始時に初期値へ戻します。
- 撮像・解析・送信・整定待ちを直列実行し、同じ未補正画像に対して重複送信しません。
  撮像結果は `slit_guide_image_loop.fit` に保存し、画面を更新します。
- 露光中に停止した場合は露光完了・保存後に停止します。
  解析・送信が始まっている場合は現在の処理を終えて停止します。
- 冷却・露光・通信タイムアウト、点源欠落などは追尾停止・切断してエラー表示します。
  ASCOMの同期呼び出し自体が戻らない場合はPython側から強制中断できません。

```powershell
uv run python -m unittest discover -s scat_observation/scat_guide_tracking_system/test_all -p "test_*.py" -v
```

MoTのJSON形式・タイムアウト・応答照合を検証します。
実カメラ・MoTの動作と、スリットで分断された星像の検出精度は実機検証が必要です。

## RA/Dec補正の改善ロジック（現在の実装）

`src/auto_guide.py` の `Correction` に実装済みです。
星位置をp、スリット中心をs、pixelからMoTのRA/Dec補正量への2×2変換行列をMとすると、
送信量は `gain × M × (s-p)` です。次画像で残差を測り、補正を繰り返します。

さらに、前回送った補正量uと次画像で観測した星の移動dから、行列を更新します。

```text
d = 今回の星位置 − 前回の星位置
M候補 = M + adaptive_rate × (u − M d) dᵀ / (dᵀ d)
```

同じ移動dを行列で補正量へ戻したとき、実際に送ったuと一致する方向へ調整する仕組みです。
たとえば、1 pixelあたり1単位と想定して2単位送ったのに1 pixelしか動かなければ、
必要な補正係数を増やす方向に更新します。既定の更新率は0.05です。

制限は以下のとおりです。

- 移動が0.2 pixel超かつ `max_target_jump_px`（既定15）未満で、推定応答と送信量が同方向の場合のみ更新。
- 初期行列に対する相対変換の特異値を0.5～2に制限し、向きの反転を許さない。
- `gain=0.5`、`deadband_px=0.5`、`max_correction=10`。単位はMoTと初期行列の定義に従う。
- 行列はメモリー上で更新し画面表示する。ファイルには保存せず、追尾開始ごとに初期値へ戻す。

これは初期校正を微調整する方式で、自動校正の代替ではありません。
現在の初期行列は単位行列の仮値です。RA/Decの単位・符号・回転は実機で初期校正が必要です。
シーイング、飽和、バックラッシュ、整定不足と補正による移動を分離していません。
同じ方向にしか動かない場合、2×2行列のすべての成分は十分に学習できません。
実際に誤差が改善したかを評価して更新を巻き戻す仕組みも未実装です。
実機での改善効果は未検証で、今回は模擬応答の倍率ずれが更新で縮まることをテストしています。
